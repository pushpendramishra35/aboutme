Case study / 01 React Native · Modernization

Modernizing a production app across 15 React Native versions

Problem A revenue-critical hospitality app was stuck on React Native 0.62. Dependencies had drifted, custom native modules blocked upgrades, and the New Architecture was on the horizon with no clear path to it.

Decision Upgrade incrementally rather than rewrite. Move version by version, keep the old bridge working while migrating custom native modules to TurboModules behind the interop layer, so releases never had to stop.

Result Reached 0.77.2 on the New Architecture with TurboModules live on iOS and Android, and trimmed the bundle 15% along the way. The reliability work that rode alongside it is case study 02.

Case study / 02 Reliability · Production

Cutting a production crash rate from 2.90% to 1.67%

Problem An inherited app was crashing for nearly 3% of sessions. Raw crash volume pointed at symptoms, not causes, and several clusters traced back across the JavaScript–native boundary.

Decision Triage by impacted users rather than raw counts, fix the highest-leverage clusters first, and add guards where undefined data crossed the JS–native bridge instead of patching each screen.

Result Crash rate dropped from 2.90% to 1.67% on a codebase that kept shipping features the whole time.

Case study / 03 Mobile security · Banking

Taking a regulated banking app through penetration testing

Problem A retail and corporate banking app had to pass third-party penetration testing before store release, hardened across identity, transport, application and device layers.

Decision Build security in by layer: Auth0 (OAuth 2.0 / OIDC) with biometrics and MFA, certificate pinning, anti-tampering, and root/jailbreak detection with encryption at rest — then work through the pen-test findings before submission.

Result Shipped with every finding remediated and no open critical or high issues.
