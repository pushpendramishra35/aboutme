Case study / 01 · React Native modernization

Modernizing a production app across 15 React Native versions

Taking a revenue-critical hospitality app from React Native 0.62 to 0.77.2 and the New Architecture, migrating custom native modules to TurboModules without ever stopping the release train.

0.62 dependency migration native compatibility build systems New Architecture TurboModules 0.77.2

Context

A production hospitality app was several years behind on React Native. It shipped real revenue, had a live user base on both stores, and carried custom native modules written against the old bridge. Standing still was becoming its own risk: dependencies were falling out of support, and the New Architecture was clearly where the ecosystem was heading.

Problem

The gap from 0.62 to current was 15 minor versions. Each carried breaking changes in dependencies, Gradle/CocoaPods, and native APIs. The custom native modules were the hardest part — they had to keep working on every intermediate version while the bridge itself was being replaced by TurboModules.

Constraints

  • Releases could not stop. The app had to keep shipping features throughout.
  • No full rewrite — the risk and cost were not justifiable.
  • Both platforms (iOS and Android) had to stay releasable at every step.

Technical decision

Upgrade incrementally rather than jump. Move version by version, resolving dependency and native breakage at each step, and adopt the New Architecture's interop layer so the old bridge and TurboModules could coexist. That let me migrate custom native modules one at a time instead of in a single high-risk cutover.

Implementation

  • Stepped through minor versions, fixing dependency and build-system breakage before touching product code.
  • Enabled the New Architecture with the interop layer so legacy bridge modules kept working.
  • Migrated custom native modules to TurboModules on iOS (Swift/Objective-C) and Android (Kotlin) one module at a time, behind the interop boundary.
  • Enabled Hermes and cleaned stale native build artifacts, which also reduced bundle size.
  • Kept the app releasable at each step, so feature work never had to pause.

Trade-offs

Incremental is slower in calendar time than a big-bang upgrade and requires discipline to avoid leaving modules half-migrated. In exchange, risk stays bounded at every step and the app is never un-shippable — which is the right trade for a revenue-critical production app.

Result

  • Reached React Native 0.77.2 on the New Architecture, with TurboModules live on both platforms.
  • Production crash rate fell 42% (2.90% → 1.67%) over the stabilization that came with it.
  • Bundle size dropped 15% (89 → 76 MB) from Hermes and build cleanup.
  • Releases continued throughout the migration.

What I took from it

On a live product, the safest migration is the one that keeps the app releasable at every commit. The interop layer is what makes that possible on the New Architecture — it turns a terrifying cutover into a sequence of small, reversible steps.
