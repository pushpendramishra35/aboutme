AI-Augmented Engineering

Using AI as engineering leverage, not autopilot

How I fold AI coding agents and LLM APIs into a normal senior engineering workflow — faster on the mechanical work, with architecture, security, tests and what ships still owned by a human.

Context

Most of my work is inherited production code: React Native apps mid-upgrade, dashboards with years of accumulated decisions, native modules nobody remembers writing. The slow parts are rarely the typing. They are understanding an unfamiliar codebase, reproducing a bug, planning a safe change, and covering it with tests. That is where AI actually helps — if it is kept on a short leash.

The bottleneck

Take a concrete example: a recurring crash cluster in a large RN codebase after a version bump. Traditionally the cost is hours of manual log reading, grepping call sites, and guessing at which native change drifted. The fix is often small; finding it is not.

How I work with AI

  • Understand. Repository-aware agents (Claude Code, Codex, Cursor) to map call sites, summarise an unfamiliar module, and surface the likely blast radius of a change before I touch it.
  • Plan. Turn an ambiguous ticket into an implementation plan — alternatives and trade-offs written down first, so the change is decided before it is coded.
  • Build. Agents for implementation and large mechanical refactors against a clear spec. Anything non-trivial gets reviewed diff by diff, not accepted wholesale.
  • Verify. AI-assisted test generation and a second-pass review to catch edge cases, then human validation, static analysis and the normal CI gates before merge.
  • Own. Architecture, security, performance and the release decision stay mine. The model assists; it does not decide what ships.

Where the leverage is real

  • Reading and summarising unfamiliar production code before a change.
  • Repetitive, mechanical refactors across many files (safer to review than to hand-edit).
  • Draft tests and edge-case discovery on paths that were previously untested.
  • Log and error investigation — narrowing a crash cluster to a few suspects fast.
  • Migration notes and documentation that would otherwise never get written.

Building software that uses AI

Separately from using AI to build software, I have shipped software that uses it: an LLM-API content pipeline (research → script → video) with prompt design, structured-output validation, tool-enabled orchestration including MCP, and failure recovery so it runs unattended. That work taught the parts that matter in production AI features — latency and cost, guardrails, fallbacks, and validating model output instead of trusting it.

The non-negotiable

Generated code is reviewed and tested exactly like code I write by hand. AI shortens the path to a change; it does not lower the bar for what is correct, secure and maintainable. That line is the whole point — it is why AI makes me faster without making the work less trustworthy.
