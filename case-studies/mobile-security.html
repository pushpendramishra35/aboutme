Case study / 03 · Mobile security

Taking a regulated banking app through penetration testing

Hardening a retail and corporate banking app across four layers — identity, transport, application and device — and remediating every third-party pen-test finding before store release.

IdentityAuth0 · OAuth 2.0 / OIDC · biometrics · MFA
TransportCertificate pinning
ApplicationAnti-tampering · integrity checks
DeviceRoot / jailbreak detection · encryption at rest

Context

A banking product covering retail and corporate customers had to ship to the App Store and Google Play under real regulatory scrutiny. Before release it needed to pass third-party penetration testing, which meant security had to be designed in rather than bolted on.

Problem

Mobile banking has a wide attack surface: stolen credentials, intercepted traffic, tampered binaries, and compromised (rooted or jailbroken) devices. Each needs a different control, and a gap in any one layer can fail the audit.

Approach — hardening by layer

  • Identity. Auth0 with OAuth 2.0 / OIDC, biometric login and MFA, with a consistent session and token-refresh model.
  • Transport. Certificate pinning so the app only trusts the expected server identity, blocking interception.
  • Application. Anti-tampering and integrity checks so a modified build refuses to run against production.
  • Device. Root and jailbreak detection, with encryption at rest for sensitive local data.

Penetration testing

Once the layers were in place, I worked directly with the penetration-testing team: reproduced each finding, fixed the root cause rather than the symptom, and re-tested. Anything that could weaken the audit trail or the security posture was closed before submission.

Result

  • Every penetration-test finding remediated before store submission.
  • Shipped with no open critical or high-severity issues.
  • Security controls spanned all four layers, not just authentication.

What I took from it

Security in a regulated app is a layered property, not a feature. The useful mindset is to assume each layer will be probed and to make sure no single control is load-bearing on its own.
