Engineering notes

Short lessons from production work

Reusable notes from real React Native and mobile work — the decision or failure mode behind each one, not just what was shipped.

Reliability

Triage crashes by impacted users, not raw volume

A high-count crash can affect a handful of retry-looping sessions, while a lower-count one takes out a whole cohort. Ranking Crashlytics clusters by impacted-user count changed which bugs I fixed first and moved the crash rate faster. The other half was guarding the JS–native bridge where undefined data crossed it, instead of patching each screen.

React Native · New Architecture

Migrate native modules to TurboModules incrementally

The interop layer lets the old bridge and TurboModules coexist. That turns a terrifying all-at-once cutover into one module at a time, so the app stays releasable at every step. On a live product, staying releasable is worth more than migrating fast.

Connected hardware

Re-subscribe BLE on the connection-state callback, not on mount

A device kept dropping its link when the app backgrounded because re-subscription was tied to component mount. Moving it onto the connection-state callback and adding a bounded retry took field reconnect success from flaky to consistently above 99%. The lesson: bind hardware lifecycle to the hardware’s state, not the UI’s.

Performance

Most bundle bloat is leftovers, not features

An 89 MB build was mostly stale native artifacts and unoptimized images accumulated across upgrades. Cleaning build outputs, enabling Hermes and Proguard/R8 shrinking, and compressing assets took it to 76 MB with faster cold starts and no feature removed.

Security

Security is a layered property, not a feature

Passing a bank’s penetration test meant no single control could be load-bearing on its own: identity, transport, application and device each needed their own defense. Working through findings, I fixed root causes rather than symptoms so a re-test wouldn’t reopen them.

CI/CD

Automating releases removes the scary part: the human steps

A manual release took ~2 days of careful hand-holding and was where mistakes happened. Moving code signing, staged rollouts and release-health checks into Fastlane took it to ~2 hours and made releases boring — which is the goal.
